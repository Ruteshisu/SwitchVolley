# 経過メモ / ハマりどころ / 質問 / 改善案

## 現在の状態（完成）
- デモ（AI同士）: 起動約5秒で最初のスパイクが必ずスーパースパイク（スロー＋横アングル）→ 3点先取で勝利演出（紙吹雪・オービットカメラ）→ デモ再開のループ
- 人間操作（サーブ/レシーブ/トス/スパイク/ブロック）は `?bot=1` で全経路を確認、手動キー入力・仮想パッド（タップで開始、十字キーの押下/解放）も確認済み
- 勝利/敗北リザルト、ポーズ、タイトル復帰を確認済み。効果音は全種類を実行してエラーなしを確認（音色の聴感確認は未実施）
- キャラ: 日向・影山（CROWS）vs 及川・牛若（RIVALS）風のファン制作キャラ。トゥーン塗り＋輪郭線、アニメ風の目、髪型・体格・ユニフォームで描き分け（個人で遊ぶ範囲を想定。作品名・ロゴは不使用）
- 個性: 影山→日向は速攻トス（低く速い、成功すると「変人速攻!!」）、牛若は左利き＆スーパースパイク率高、及川はジャンプサーブ率高、セッター役（影山・及川）は1本目を取りにくくトスに回る

## 開発・検証の手順
- `python tools/serve.py 8765` → http://localhost:8765 （`.claude/launch.json` に登録済み）
- `tools/lineup.js` … `?play=1` で開いてコンソールで実行すると4人を正面から並べて見た目確認できる
- `?bot=1` 人間側を完璧タイミングで自動操作 / `?play=1` デモを飛ばす / `?log=1` イベントを console と `SV.debug.log` に記録 / `?pad=1` PCでも仮想パッド表示
- 例: `SV.debug.log.map(x=>x.join(' ')).join('\n')` でラリー経過を確認

## 拡張のしかた（入口）
- バランス調整: `js/config.js` のみ（タイミング窓・AI成功率・得点数・打球の滞空時間）
- キャラ・チーム名・ユニフォーム: `js/roster.js` だけで完結（髪型・目・眉・口・体格・左利き・AI個性）。チーム0の先頭が人間操作
- 新しい髪型: `character.js` の `buildHair()` に分岐を追加
- 新しいモーション: `character.js` の `POSES` にポーズを追加し `setPose(name, hold, after)` で呼ぶ
- 新しい打球: `match.js` の `resolve()` / `doSpike()` に分岐を追加。打球は `ball.launch(目標, 滞空時間)` か、ネット越えなら `safeLaunch()`
- 新しい効果音: `audio.js` の `sfx` に関数を追加し `SV.audio.play(name)`

## ハマりどころ（再発しそうな件）
- **JS 修正が反映されない**: `python -m http.server` はキャッシュ制御なし → 古い JS が使われる。`tools/serve.py`（no-store）を使う
- **ES Modules 不使用の理由**: file:// で開くと CORS で module が読めない。classic script + `SV` 名前空間で依存順に読み込む（`index.html` の順番を崩さない）
- **three.js r128**: cdnjs で UMD 版(`three.min.js`)がある最後の系列。`CapsuleGeometry` は無い（円柱+球で代用）
- **BackSide の薄い Box** を壁の帯に使うと上面が天井として描画される → 帯は Plane で作る
- **ブラウザペインのビューポートエミュレーション**中のスクリーンショットは縮小表示されるだけ（ゲームの不具合ではない）。resize イベントが来ない環境に備え毎フレームサイズ監視（`main.js fitIfChanged`）
- ブラウザペインで file:// を開くと静的スナップショット表示になり JS が動かない → 検証は localhost で行う
- 人間のタイミング判定は「ゲーム内時間」基準。スロー中は実時間で判定が長くなる（意図通り）
- AI の成否は plan 作成時に決め、失敗時は移動先をずらして「届かない」形で自然に見せている
- トゥーン塗りは光源が強いと白飛びする（肌が白く見えた）→ グラデーションの最大値を 205 に抑え、肌色をやや濃く
- 前髪を球面に沿った板で作ると「ヘルメットのバイザー」に見える → 下向きの細い円錐を並べてギザギザの毛先にする
- 輪郭線は法線方向に膨らませた裏面描画。Box/Cylinder の角は頂点が分かれているので角に小さな切れ目が出る（許容）

## 本来確認したかった点（自己判断で決めたもの）
- 試合形式: 1セット 7点先取（デモは 3点）、デュースなし → `config.js` の `MATCH` で変更可
- インドア 2vs2。ローテーションは簡略化（サーブ権を取り返すたびに同チーム内でサーバー交代）
- 移動は自動 + 手動補正（スイッチスポーツ同様）。完全手動は `config.js` の `AUTO_MOVE: false`
- 人間は常に日向風キャラ（#10）。パートナーの影山風は AI。2人協力・対人戦、キャラ選択は未対応
- 相手チームは及川風（白×ターコイズ #1）と牛若風（白×紫 #1）の混成のため、ユニフォームは個人ごとに別色
- 難易度選択なし（AI 強さは `config.js` の `AI`）
- ゲーム名はオリジナルの「SPIKE STADIUM」（既存タイトルの名称・ロゴ・キャラは不使用）

## 外部素材があれば良くなる点
- キャラ: プリミティブの組み合わせ（髪・目で雰囲気は出せるが顔の作り込み・等身は限界あり）。VRoid Studio 等で作った VRM/glTF モデル + GLTFLoader/three-vrm（three.js 以外の追加ライブラリ）が使えれば原作に近い見た目にできる
- 効果音: WebAudio 合成のため打球音・歓声がやや電子的。実録音サンプルがあると臨場感が上がる
- 観客: InstancedMesh の箱人形。観客スプライトシートがあると密度感が増す
- フォント: システムフォント依存。ロゴ用 Web フォントがあるとタイトルが映える
- ポストエフェクト（three.js の examples にある Bloom 等）は追加ファイル扱いのため不使用。使えればスーパースパイクの光がより派手になる
