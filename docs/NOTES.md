# 経過メモ / ハマりどころ / 質問 / 改善案

## 現在の状態
- 全モジュール実装済み。デモ（AI同士）→ 約5秒でスーパースパイクのスロー演出 → 3点先取で勝利演出 → デモ再開、のループが動作
- 人間操作（サーブ/レシーブ/トス/スパイク/ブロック）は `?bot=1` の自動入力で全経路を確認済み
- 残: スマホ仮想パッドの実機相当確認、手動プレイ確認、仕上げ

## 開発・検証の手順
- `python tools/serve.py 8765` → http://localhost:8765 （`.claude/launch.json` に登録済み）
- `?bot=1` 人間側を完璧タイミングで自動操作 / `?play=1` デモを飛ばす / `?log=1` イベントを console と `SV.debug.log` に記録
- 例: `SV.debug.log.map(x=>x.join(' ')).join('\n')` でラリー経過を確認

## ハマりどころ（再発しそうな件）
- **JS 修正が反映されない**: `python -m http.server` はキャッシュ制御なし → ブラウザが古い JS を使う。`tools/serve.py`（no-store）を使う
- **ES Modules 不使用の理由**: file:// で開くと CORS で module が読めない。classic script + `SV` 名前空間で依存順に読み込む（`index.html` の順番を崩さない）
- **three.js r128**: cdnjs で UMD 版(`three.min.js`)がある最後の系列。`CapsuleGeometry` は無い（円柱+球で代用）
- **BackSide の薄い Box** を壁の帯に使うと上面が天井として描画されてしまう → 帯は Plane で作る
- **ブラウザペインのビューポートエミュレーション**中のスクリーンショットは縮小表示されるだけ（ゲーム側の不具合ではない）。resize イベントが来ない場合に備え毎フレームサイズ監視している（`main.js fitIfChanged`）
- 人間のタイミング判定は「ゲーム内時間」基準。スロー中は判定が実時間で長くなる（意図通り）

## 本来確認したかった点（自己判断で決めたもの）
- 試合形式: 1セット 7点先取（デモは 3点）、デュースなし → `config.js` の `MATCH` で変更可
- インドア 2vs2。ローテーションは簡略化（サーブ権を取り返すたびにサーバー交代）
- 移動は自動 + 手動補正（スイッチスポーツ同様）。完全手動にしたい場合は `config.js` の `AUTO_MOVE: false`
- 人間は常に青チームの #1。パートナー(#7)は AI
- ゲーム名はオリジナルの「SPIKE STADIUM」（既存タイトル名やロゴは使わない）

## 外部素材があれば良くなる点
- キャラ: 現状はプリミティブの組み合わせ。glTF のリグ付きモデル + モーションキャプチャがあればフォームが格段に自然になる
- 効果音: WebAudio 合成のため打球音・歓声がやや電子的。実録音の打球音/歓声サンプルがあると臨場感が上がる
- 観客: InstancedMesh の箱人形。スプライトシート（多様な観客イラスト）があると密度感が増す
- フォント: システムフォント依存。ゲーム用のロゴフォント（Webフォント）があるとタイトルが映える
